# Security Policy — Shard.js

## Supported Versions

We provide security updates and patches for the following versions:

| Version | Supported          |
| ------- | ------------------ |
| 0.2.x   | :white_check_mark: |
| < 0.2.0 | :x:                |

## Reporting a Vulnerability

If you discover a security vulnerability in Shard.js, please report it responsibly:

1. **Do NOT open a public GitHub issue.**
2. Send an email to `security@shardjs.dev` (or the maintainer email specified in `package.json`).
3. Include the following details in your report:
   - Description of the vulnerability and attack vector.
   - Affected package(s) (`@shardjs-framework/core`, `@shardjs-framework/api`, `@shardjs-framework/cli`, `@shardjs-framework/plugin-drizzle`, `create-shard`).
   - A minimal reproduction script or curl command demonstrating the issue.
   - Potential impact and severity assessment.

## Vulnerability Response Process

- **Acknowledgement:** We will acknowledge receipt of your report within 48 hours.
- **Assessment:** We will confirm the vulnerability, assign a severity level, and prepare a fix.
- **Release:** We will release a security patch and publish an advisory acknowledging your contribution (unless you prefer to remain anonymous).
